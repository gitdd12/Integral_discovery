# 성능 탐정 (가설 세우고 측정하는 1~2시간)

목적: "알고리즘 문제 풀이"가 아니라 **가설 → 예측 → 측정 → 확인** 과정이 재미있는지 보는 시험.

## 할 일
1. `python order_report.py` 로 실행해 본다(약 10초). `report.txt` 가 만들어진다.
2. **코드를 읽고 느린 이유를 가설로 적는다.** (LOG.md 에 기록. 측정하기 전에!)
3. 각 가설마다 **예측**을 적는다. 예: "이 함수가 전체 시간의 대부분일 것이다 / 3초 이상일 것이다".
4. 측정한다. 방법은 스스로 찾는다 (`time.time()` 으로 구간 재기, `python -m cProfile -s cumtime order_report.py` 등).
5. 가설이 맞았는지 확인하고, 하나씩 고친다. 고칠 때마다 다시 측정.
6. 결과 검증: `python order_report.py` 후 `md5sum report.txt` 가 `expected_md5.txt` 와 같아야 한다 (출력이 달라지면 안 됨).

## 규칙
- **AI 에게 "어디가 느린지 찾아줘"라고 하지 않는다.** 도구 사용법(cProfile 읽는 법 등)과 개념(시간복잡도가 뭔지)을 묻는 건 괜찮다.
- 막히면 막혔다고 LOG.md 에 적고 계속한다. 답은 `ANSWER.md` 에 있지만 **끝나기 전에 열지 않는다**.

## 끝난 뒤 (LOG.md 하단 질문에 답하기)
- 가설이 틀렸을 때 기분은?
- 측정하는 순간과 고치는 순간 중 어느 쪽이 더 재미있었나?
- 같은 일을 세 시간 더 해도 괜찮은가?
